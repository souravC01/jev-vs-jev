# Jev-only experiment implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Jev × Laya simulation with one real Jev self-judgment per submitted task.

**Architecture:** Keep the Next.js page and `POST /api/evaluate`. The route validates input and calls a single Jev client; the client validates the official `noul` answer and maps it to a binary verdict. The page displays the result or an explicit error.

**Tech Stack:** Existing Next.js 15, React 19, TypeScript, Tailwind CSS, Zod, and Vitest. No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-23-jev-only-design.md`

## Global Constraints

- One Jev HTTP request per submitted task, using `model: "jev-latest"`.
- Server-side `TYPESAFE_API_KEY`; no simulation or silent fallback.
- A `noul` value of 0.5 maps to YES; lower values map to NO.
- Display the chosen answer's probability, not a separate confidence statistic.
- Task length remains 1–2,000 trimmed characters.
- Keep the page playful and responsive; do not add Laya, persistence, accounts, or analytics.

## Review Focus

- Missing key: return a configuration error and no verdict.
- Hanging upstream request: abort after a short timeout and show retry.
- HTTP 401/429/5xx: show a sanitized error and no verdict.
- Missing, nonnumeric, or out-of-range `answers.fit.noul`: reject the response.
- URL task longer than 2,000 characters: reject before an API request.
